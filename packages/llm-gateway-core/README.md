# @swag/llm-gateway-core

Ядро LLM Gateway (спеки 002 и 004): проверка и вызов модели, расчёт стоимости, резерв и списание денег роя. Чистый TypeScript, не знает про HTTP, Fastify, Postgres, LiteLLM и env. Всё внешнее приходит через порты, которые объявляет ядро.

## Задачи

- Проверить тело `POST /v1/chat/completions` по схеме `ChatRequest` и запретить поля ключа и адреса провайдера (REQ-002-18): `parseChatRequest` возвращает разобранное тело или текст `message` для `invalid_request`.
- Отдать `GET /v1/models` из каталога и сверить каталог с моделями апстрима при старте (`checkUpstream`, REQ-002-2, AC-002-6, AC-002-18). `createLlmGatewayCore(deps)` даёт `info`, `listModels`, `checkUpstream`, `complete`, `registerSwarm`, `closeSwarm`, `releaseHolds`.
- Регистрация роя и агентов (спека 004, 4.2, REQ-004-6, AC-004-4): `registerSwarm(raw)` проверяет тело `LlmSwarmRegistration` и бюджет агента не больше бюджета роя (`400 invalid_request`), модели агентов в каталоге (`400 model_not_found`), затем `BudgetStore.register` (`409 swarm_registered`). `closeSwarm(swarmId)` — `200` с `spentMicroUsd`, повтор — тот же ответ, неизвестный рой — `404 not_found` (AC-004-8).
- Проверка вызова до апстрима (REQ-002-4, REQ-004-4…REQ-004-7, AC-002-3…-5, -28, AC-004-6, -7): вызывающий `LlmCaller` → `invalid_caller`, тело `ChatRequest` → `invalid_request`, модель каталога → `model_not_found`, `BudgetStore.findAgent` — нет агента, рой закрыт или срок истёк → `403 caller_not_registered`, модель не модель агента → `403 model_not_allowed`. Отказ — `{ kind: 'error' }`, без события, без резерва, без апстрима; на шагах 2–7 — лог `warn` `call_refused` с `code`.
- Резерв и списание (спека 004, 4.3, REQ-004-8…REQ-004-12, AC-004-10…AC-004-12, AC-004-15, AC-004-16): после проверок `max_tokens ?? max_completion_tokens` должно быть целым ≥ 1 (иначе `400 invalid_request`), `holdMicroUsd(inputBytes, maxOut, prices)` резервируется через `BudgetStore.reserve` (`402 swarm_budget_exceeded` / `agent_budget_exceeded`). Цены модели — из `PriceBook`. Далее вызов апстрима (без потока или с потоком); списание `BudgetStore.settle` выполняется до публикации `llm.call` — при любом итоге: успех, отказ апстрима (charge 0, `none`), обрыв потока, исключение ядра или апстрима.
- Исключение вне порта апстрима (ядро закрывает резерв): резерв закрывается как сетевой отказ — событие `status: 'error'`, `charge` 0, `none` — и исключение пробрасывается дальше. `settle` вызывается ровно один раз.
- Сбой `settle` не меняет ответ клиенту: лог `error` `settle_failed`, событие публикуется, резерв остаётся до перезапуска (REQ-004-13, AC-004-17). Списание сверх резерва — лог `warn` `hold_exceeded` (REQ-004-12, AC-004-16).
- Применение цен (спека 004, 4.9, AC-004-28, AC-004-40 — `applyStoredPrices`): `applyOpenRouterPrices(catalog, response)` берёт цены из ответа OpenRouter по `openRouterModel` и возвращает `changed` и `skipped` с причиной; `applyStoredPrices(catalog, stored)` кладёт сохранённые цены поверх каталога. Обе чистые; таймер, запросы к OpenRouter и запись в `PriceStore` — оболочка (T-9).
- Снятие резервов при старте (REQ-004-14, AC-004-18): `releaseHolds()` вызывает `BudgetStore.releaseHolds` без списания и пишет лог `warn` `hold_released` на каждый резерв; возвращает число резервов. Оболочка вызывает его до приёма запросов.
- Успешный `complete` без потока (REQ-002-1, REQ-002-7, REQ-002-19, AC-002-1, -9, -14, -29): `callId`, замер задержки, `usage` и стоимость по `PriceBook`, событие `llm.call` `status: 'ok'`, лог `llm call`, `usage_missing` без `usage`, `event_publish_failed` при сбое шины.
- Отказ апстрима без потока (REQ-002-9, AC-002-15, -16 на уровне ядра, AC-030-8): таблица 4.6 — `400 upstream_bad_request`, `429 rate_limited`, `502 upstream_error`, `504 upstream_timeout`; событие `status: 'error'` с `usage: null`, лог `llm call` warn с `upstreamStatus` (только в лог). Обрыв клиентом — `aborted` без `errorCode`.
- Поток `complete` с `stream: true` (T-17, T-18, REQ-002-8, AC-002-10, -12, -13, -15, -29): `stream_options.include_usage = true` в копии тела, payload'ы отдаются клиенту как пришли, `usage` берётся из последнего фрагмента. Байты выхода учитываются по фрагментам, дошедшим до потребителя (до `yield`). Событие и списание — в `finally` генератора. Обрыв апстрима после старта — последний payload `{"error":…}`, событие `status: 'aborted'` с `errorCode`. Внешний `aborted` (клиент ушёл) — исключение потребителю, без payload ошибки и без `errorCode`.

## Что внутри сейчас

- `complete(rawCaller, rawBody, signal)`: проверки по 4.2 по порядку — `LlmCaller` (`invalid_caller`), `parseChatRequest` (`invalid_request`), модель в каталоге (`model_not_found`, имя обрезается до 100 символов), `findAgent` и модель агента (`caller_not_registered`, `model_not_allowed`), `max_tokens` (`invalid_request`). Отказы шагов 2–7 — `refuseCall` (лог `call_refused`). Далее `reserve` (шаг 8, отказ — `402` и лог `budget_exceeded`) и вызов: `streamReply` для потока, `jsonReply` для обычного ответа. Оба закрыты общим `try`: при исключении — `upstreamFailed` с `{ kind: 'network' }`, затем `throw`.
- `publishCall` — общий путь для успеха и отказа: `chargeFor` → `BudgetStore.settle` (флаг `settled`, один раз) → лог `hold_exceeded` при превышении резерва → событие `llm.call` с `charge` → лог `llm call` (info при `ok`, warn иначе; у обычного вызова с обрывом клиентом — info, спека 030). Сбои `settle` и публикации — логи `settle_failed` и `event_publish_failed`, ответ клиенту не меняют.
- `upstreamFailed` — отказ апстрима по 4.6 (`upstreamReply`) или обрыв клиентом (`aborted`) для обычного вызова и потока; `refuseCall` — отказ до апстрима с логом `call_refused`.
- `costMicroUsd(usage, prices)` — формула 4.3 в `bigint`: цены из строк × 10⁴, `cached = min(cachedPromptTokens, promptTokens)`, округление вверх.
- `inputBytes(body)` — UTF-8 длина `JSON.stringify({ messages, tools: tools ?? [] })` через `TextEncoder`; `holdMicroUsd(inputBytes, maxOut, prices)` = `ceil((inputBytes·p_in + maxOut·p_out) / 10⁴)`; `outputBytes(message)` — UTF-8 длина `content` и `tool_calls[].function.arguments` одного `message` или `delta`; `chargeFor(call, prices)` — `usage` есть при любом статусе → `costMicroUsd`/`usage`; нет `usage` при `ok`/`aborted` → `estimate`; `error` → 0/`none` (4.3). Все четыре — чистые, без Node API; `TextEncoder` объявлен минимально в `src/env.d.ts` (lib ES2023 его не содержит, DOM и `@types/node` не подключаются).
- `parseUsage(raw)` — `prompt_tokens` → `promptTokens`, `completion_tokens` → `completionTokens`, `prompt_tokens_details.cached_tokens` → `cachedPromptTokens` (нет поля — 0). Возвращает `null`, если нет `prompt_tokens` или `completion_tokens` или они не целые ≥ 0.
- `parseProviderCost(rawUsage)` — `usage.cost` как конечное число ≥ 0 → `Math.round(cost × 10⁶)`; иначе `null`.
- `applyOpenRouterPrices(catalog, response)` и `applyStoredPrices(catalog, stored)` — спека 004, 4.9. Перевод цены: `perMTokPrice` — десятичный сдвиг строки на 6 знаков через `BigInt` с округлением вверх до 4 знаков и проверкой `PricePerMTok`; `pricesFromPricing` — маппинг `prompt`, `completion`, `input_cache_read` (нет — `prompt`); `extraChargeReason` — пропуск при ненулевых `request`, `image`, `web_search`. `samePrices` — сравнение через `scaledPrice`. Результат `changed` — `PriceChange` (`model`, `from`, `to`), `skipped` — `PriceSkip` (`model`, `reason`).
- `parseChatRequest(raw)` — сначала поля `CLIENT_CREDENTIAL_FIELDS` (`Client-side provider credentials are not allowed: <поле>`), потом схема `ChatRequest` (zod `looseObject`); первые 3 ошибки Zod как `path: message` через `; ` (D-43).
- `createLlmGatewayCore(deps: LlmGatewayDeps)` — фабрика ядра (4.4). `deps`: `catalog` (список моделей, уже разобран оболочкой), `upstream: LlmUpstream`, `events: EventPublisher`, `clock: Clock`, `ids: Ids`, `trace: TraceContext`, `log: Logger`, `version`, `budgets: BudgetStore`, `prices: PriceBook`.
- `PriceBook` (`prices(model)`) — единственный источник цен для `costMicroUsd`, `holdMicroUsd` и `chargeFor`. Цены каталога (`ModelCatalog.models[].prices`) больше не используются для денег; каталог даёт только список моделей. Цены в проде отдаёт PriceBook поверх `models.json` и OpenRouter (спека 004, 4.9).
- Порты денег (спека 004, 4.4): `BudgetStore` (`register`, `findAgent`, `reserve`, `settle`, `close`, `releaseHolds`), `PriceStore` (`load`, `save`); типы `RegisteredAgent`, `ReserveResult` (`ok: true` или `swarm_budget_exceeded` / `agent_budget_exceeded`), `LedgerEntry` (одна запись на `callId`, основание списания `ChargeBasis`), `StoredPrice`. Типы `LlmSwarmRegistration` и `ChargeBasis` — из `@swag/contracts`.
- `listModels()` — `{ object: 'list', data }` по порядку каталога, `owned_by: 'swag'`; апстрим не вызывается.
- `checkUpstream(signal)` — `listModels` апстрима; все `id` каталога есть → `{ ok: true }`; нет части → `{ ok: false, missing }` в порядке каталога; ошибка апстрима → `{ ok: false, failure }`.
- Тесты: `test/money-formulas.test.ts` — AC-004-9 (таблицы 4.3, UTF-8); `test/money-prices.test.ts` — AC-004-28 (таблица 4.9, равенство `"3"`/`"3.00"`, модели без `openRouterModel` и не из ответа) и AC-004-40 (`applyStoredPrices`); `test/money-register.test.ts` — AC-004-4, -6, -7, -8; `test/money-settle.test.ts` — AC-004-10 (включая `1.5`, `"10"`, `null`), -11, -12, -15 (usage, поток, обрыв, `return()` после первого фрагмента, исключение апстрима и потока), -16, -17, -18; `test/complete-checks.test.ts` — AC-002-3, -4, -5, -28 и лог `call_refused` на шагах 2–4; `test/complete-ok.test.ts`, `test/complete-errors.test.ts`, `test/complete-stream*.test.ts`, `test/llm-gateway-core.test.ts`, `test/gateway-core.test.ts` — поведение 002.
- Фейки: `test/fake-budgets.ts` — `BudgetStore` в памяти с условиями 4.5 (лимиты роя и агента, резерв, списание один раз на `callId`); неизвестный агент в `reserve` — `agent_budget_exceeded`. `test/fakes.ts` — порты в памяти (`fakeUpstream`, `chunksThen` с флагом `closed`, `fakeEvents`, `fakeClock`, `fakeIds`, `fakeLog`, `fakePrices`, `fakeDeps`). `fakeDeps` по умолчанию регистрирует рой `TEST_SWARM` через `budgets.seed` (`registered: false` — без регистрации).

## Ограничения

- `holdMicroUsd` и `chargeFor` ожидают целые неотрицательные аргументы: `BigInt` на нецелом бросает `RangeError`. Проверка `maxOut` — в `complete` (спека 004, 4.3, шаг 7).
- Резерв потока освобождается только при итерации потока: если потребитель не начал читать поток, генератор не запускается и `finally` с `settle` не выполняется. Резерв висит до перезапуска (`releaseHolds`). Сброса по таймауту нет, см. D-93 в `docs/spec/questions.md`.
- Освобождение резервов при старте рассчитано на один процесс gateway (спека 004, раздел 2, «Не входит»).

Правила ядра ([архитектура](../../docs/architecture.md), [спека 000, 4.2](../../docs/spec/000-foundation.md#42-правила-ядра-и-оболочки)):

- Зависимости — `@swag/contracts` и `zod`. `zod` по 4.14 нужен для схемы `ChatRequest`.
- Нет Node API, `process`, env, файлов, сети: `tsconfig` без `@types/node` и DOM.

Нарушения ловят `npm run arch:check` и `npm run typecheck`.

## Ключевые решения

- Деньги считаются в `bigint` (спека 004, 4.3): цены — строки × 10⁴, `"0.0001"` дает ровно 1 micro-USD за миллион токенов. Все округления в ядре — вверх через `ceilMicroUsd` (резерв, оценка и `costMicroUsd` — одна функция); `providerCostMicroUsd` — до ближайшего, это факт расхода платформы.
- Цены — из `PriceBook`, а не из каталога. Каталог отвечает только за список моделей; цены обновляются из OpenRouter (4.9), поэтому деньги не зависят от `models.json` в рантайме.
- Settle до публикации события: `llm.call` несёт `charge`, который уже записан в ledger. Сбой `settle` не меняет ответ клиенту (REQ-004-13). Исключение вне апстрима тоже закрывает резерв через `settle` с charge 0 и затем пробрасывается; `settled` защищает от двойного списания.
- Лог `call_refused` на шагах 2–7 (`warn`, поле `code`, у шагов 5–7 и 3–4 — ids из проверенного вызывающего, у шага 2 ids не пишутся, потому что не проверены). Шаг 8 — `budget_exceeded` по 4.3. Имя `call_refused` в спеке не задано, на подтверждение — D-92 в `docs/spec/questions.md`.
- Порядок проверок `registerSwarm` и формула `max_tokens` заданы спекой (REQ-004-6 и 4.3) и вопросов не порождают. Значение `max_tokens` — `body.max_tokens ?? body.max_completion_tokens`, любое невалидное значение (нет, `null`, `0`, нецелое, строка) — `400 invalid_request` с одним текстом `max_tokens is required`.
- Поток — генератор `relay` над `upstream.stream`: usage, `providerCostMicroUsd` и байты фрагмента запоминаются до `yield`, событие в `finally`. Ошибка апстрима после старта ловится в `catch` генератора: клиенту уходит payload ошибки, генератор завершается; `aborted` пробрасывается потребителю (D-62). Если потребитель вызвал `return()` до первого `next()`, `finally` не запустится, события не будет (D-60). `latencyMs` и `ts` потока — по концу потока (D-59). Для потока без `usage` лог `usage_missing` не пишется: вариант А, D-61. Что делать с резервом, если итерации не было, — D-93.
- Байты — UTF-8 через `TextEncoder`, а не `Buffer` и не `String.length`: кириллица и `ё` весят 2 байта (спека 004, 4.3, AC-004-9). Вход — длина JSON `{ messages, tools }`, выход — `content` и `arguments`; токены не считаются, поэтому байты — верхняя граница токенов (Q-3).
- Обычный вызов, клиент ушёл (спека 030, 4.5): порт отдаёт `{ kind: 'aborted' }`, событие `llm.call` со `status: 'aborted'`, `usage: null`, стоимости `null`, без `errorCode`, лог `llm call` уровня `info`. Ответ клиенту — `502 upstream_error`, как при `network`.
- Порядок проверок — как в 4.2: сначала вызывающий, потом тело, потом модель. Отказ возвращается значением (`kind: 'error'`), а не исключением: оболочка переводит его в HTTP-ответ по 4.6.
- Цены OpenRouter (4.9): перевод строки за токен в строку за 1 млн делается десятичным сдвигом строки, без `Number`; округление вверх до 4 знаков. Ключ сопоставления — `openRouterModel`, не id модели платформы; `input_cache_write` не учитывается (Q-8). Выходные цены — нормализованные строки без незначащих нулей (`3.00` → `"3"`), поэтому сравнение `changed` — через `scaledPrice`, а не по строке. Модели без `openRouterModel` в `skipped` не попадают; ответ без `data[]` — пустой список (D-96). Причины пропусков — английский текст (`non-zero pricing.request`, `invalid pricing.prompt`, `not in OpenRouter response`): спека текст не задаёт, это внутренний лог; имя лога `price_update_skipped` — в оболочке (T-9).
- Порты с именами и полями из 4.4: `Ids` вместо `IdGenerator`, `Clock.now()` возвращает `Date` (D-55). `latencyMs` считается сразу после ответа апстрима, до публикации (D-57).
- Имя модели в `model_not_found` обрезается по символам Unicode (`Array.from`), а не по UTF-16 единицам, чтобы не разрезать эмодзи (D-56).
- `parseChatRequest`: поля ключа и адреса проверяются до схемы; сообщение «Client-side provider credentials…» точнее, чем ошибка Zod про `messages` (D-42). Результат — `{ ok, value }` / `{ ok: false, message }`, а не исключение: оболочка переводит `message` в `400 invalid_request`.
