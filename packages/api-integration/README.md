# @swag/api-integration

Общая чистая логика для ядер, которые работают с API платформы: сейчас — проекция роя из его событий (спека 001, 4.4). Используют `api-core` (хранит состояние роя) и `ui-core` (показывает его), поэтому правило одно — в одном месте.

## Задачи

- `applyEvent(view, event)` — применить одно событие роя к `SwarmView`: статусы роя и агентов, счётчики сообщений, рёбра цепочки, результат и причина ошибки. Событие с `seq` не больше `lastSeq` игнорируется.
- `projectSwarm(events)` — состояние роя из всей последовательности событий.

## Что внутри сейчас

- `src/swarm-view.ts` — тип `SwarmView`, `applyEvent`, `projectSwarm`.
- `test/swarm-view.test.ts` — AC-001-2.

## Ограничения

Правила ядра ([архитектура](../../docs/architecture.md), [спека 000, 4.2](../../docs/spec/000-foundation.md#42-правила-ядра-и-оболочки)):

- Зависимости — только `zod` и `@swag/contracts`.
- Нет Node API, `process`, env, файлов, сети.
- Чистые функции: без состояния и побочных эффектов.

Нарушения ловит `npm run arch:check` (пакет включён в проверку как ядро, REQ-001-18).

## Связи

- Использует: `@swag/contracts` (типы событий).
- Используют: `@swag/api-core`, `@swag/ui-core` (с 001 — ui-core появляется в T-12).

## Ключевые решения

- Состояние роя — не хранимая сущность, а свёртка событий: `projectSwarm` = `reduce(applyEvent)`. Так `api` и `ui` получают одинаковый результат из одних и тех же событий (001, 4.4, T-3).
- `applyEvent` возвращает тот же объект при повторном `seq` (идемпотентность по `seq`), бросает ошибку на событие до `swarm.created` и на повторный `swarm.created`.
- Зависимость от `zod` объявлена (белый список ядер, REQ-001-18), но прямых импортов `zod` в коде нет — типы берутся из `@swag/contracts`.
- `packages/api-integration` проверяется `arch:check` как ядро (T-2, Q-5).
