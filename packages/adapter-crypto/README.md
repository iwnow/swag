# @swag/adapter-crypto

Адаптеры на криптографии: хэш пароля argon2id и непрозрачные токены (спека 012, 4.7), шифр секретов организации и подписанные гранты выхода (спека 026, 4.5, 4.7).

## Задачи

- Хэшер паролей `PasswordHasher` на `@node-rs/argon2` с параметрами 4.7 (REQ-012-8).
- Непрозрачные токены `OpaqueTokens` для токенов подтверждения и обновления: 32 случайных байта, хранится SHA-256 (REQ-012-4, REQ-012-11).
- Шифр секретов организации `SecretCipher`: AES-256-GCM, привязка к `orgId` и имени через AAD (REQ-026-7, AC-026-5).
- Гранты выхода: выдача и проверка подписи HMAC-SHA256 для `egress-proxy` (REQ-026-6, AC-026-10).
- Замер стоимости `verify` (NFR-012-1, журнал T-12): p50 8.7–8.8 мс, p95 13.7–14.2 мс, ниже нижней границы 20 мс; по NFR-012-1 параметры при этом не понижаются.

## Что внутри сейчас

- `createArgon2Hasher()` — `hash` возвращает PHC-строку `$argon2id$v=19$m=19456,t=2,p=1$…`; `verify` возвращает `false` и на неверный пароль, и на битую строку хэша, без исключения.
- `createNodeOpaqueTokens()` — `create()` даёт `randomBytes(32)` в base64url (43 символа) и SHA-256 hex; `hash(token)` — тот же SHA-256 hex.
- `createAesGcmCipher(keyBase64)` — `SecretCipher`. Ключ — ровно 32 байта в base64, иначе исключение. `encrypt(plaintext, aad)` даёт blob `iv(12) || tag(16) || шифротекст`; `decrypt(blob, aad)` бросает при неверном ключе, AAD или подмене байта.
- `createEgressGrants(keyBase64)` — `issue(grant)` выдаёт токен, `verify(token)` возвращает `EgressGrant` или `null`. Тип `GrantVerifier` объявлен здесь структурно и совпадает с портом `GrantVerifier` из `egress-proxy-core`.
- `test/crypto.test.ts` — AC-012-23, AC-012-24.
- `test/cipher.test.ts` — AC-026-5.
- `test/grants.test.ts` — AC-026-10.
- `test/bench.test.ts` — замер `verify`: 50 вызовов, p50 и p95, верхний порог 500 мс (NFR-012-1; нижняя граница не проверяется: по NFR быстрее — допустимо, параметры не понижаются). Запуск: `IDENTITY_BENCH=1 npx vitest run packages/adapter-crypto`. Без переменной тест пропускается.

## Ограничения

- Параметры argon2id зашиты в адаптер и не настраиваются из конфига: 4.7 фиксирует их.
- Хэш пароля считается в потоке библиотеки (`@node-rs/argon2` — асинхронные функции на пуле потоков).
- Ключи (`SECRETS_KEY`, `EGRESS_PROXY_KEY`) передаёт оболочка; ротации и vault нет (этап 12, спека 026).

## Связи

- Порты: `PasswordHasher`, `OpaqueTokens` из `@swag/identity-core`. Только типы.
- Типы: `SecretCipher` — интерфейс этого пакета, `@swag/adapter-postgres` импортирует его как тип; `GrantVerifier` объявлен в `egress-proxy-core`, здесь — структурно совпадающий тип.
- Использует: `@node-rs/argon2`, `@swag/identity-core`, `@swag/contracts` (`EgressGrant`), `node:crypto`.
- Потребители: оболочка `apps/identity` (T-16), `apps/api` (шифр секретов, T-9), `egress-proxy` и оркестратор (гранты, T-10, T-14).

## Ключевые решения

- Алгоритм argon2id задан числом `2` (= `Algorithm.Argon2id`): `const enum` из `@node-rs/argon2` не доступен при `verbatimModuleSyntax`. Параметры — точно из 4.7, версия по умолчанию (0x13 = `v=19`).
- Хэш токена — SHA-256 от строки base64url, та же функция `hash` для выдачи и для поиска: хранилище и выдача не расходятся по кодировке.
- Шифр: раскладка blob `iv || tag || данные` (4.5), iv — 12 случайных байт на каждое шифрование. AAD — `${orgId}:${name}`: шифротекст, перенесённый в другую организацию или под другое имя, не расшифровывается (спека 026, 4.5).
- Ключ принимается только как каноническая base64 длиной ровно 32 байта (строка должна совпадать с собственной перекодировкой): мусор, короткий ключ и запись без паддинга отсекаются при создании адаптера, а не при первой расшифровке.
- Грант: токен `base64url(JSON) + '.' + base64url(HMAC-SHA256(key, первая часть))` (спека 026, 4.7). Подпись сверяется через `timingSafeEqual`; разные длины — сразу `null` без исключения. Полезная часть, которая не JSON или не проходит `EgressGrant.safeParse`, — `null`. Любая ошибка разбора — `null`, не исключение.
