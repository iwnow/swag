# @swag/adapter-crypto

Адаптеры identity-портов на криптографии: хэш пароля argon2id и непрозрачные токены. Спека 012, 4.7.

## Задачи

- Хэшер паролей `PasswordHasher` на `@node-rs/argon2` с параметрами 4.7 (REQ-012-8).
- Непрозрачные токены `OpaqueTokens` для токенов подтверждения и обновления: 32 случайных байта, хранится SHA-256 (REQ-012-4, REQ-012-11).
- Замер стоимости `verify` (NFR-012-1): p50 ≈ 8.8 мс, p95 ≈ 14 мс, ниже нижней границы 20 мс; по NFR-012-1 параметры при этом не понижаются.

## Что внутри сейчас

- `createArgon2Hasher()` — `hash` возвращает PHC-строку `$argon2id$v=19$m=19456,t=2,p=1$…`; `verify` возвращает `false` и на неверный пароль, и на битую строку хэша, без исключения.
- `createNodeOpaqueTokens()` — `create()` даёт `randomBytes(32)` в base64url (43 символа) и SHA-256 hex; `hash(token)` — тот же SHA-256 hex.
- `test/crypto.test.ts` — AC-012-23, AC-012-24.
- `test/bench.test.ts` — замер `verify`: 50 вызовов, p50 и p95, верхний порог 500 мс (NFR-012-1; нижняя граница не проверяется: по NFR быстрее — допустимо, параметры не понижаются). Запуск: `IDENTITY_BENCH=1 npx vitest run packages/adapter-crypto`. Без переменной тест пропускается.

## Ограничения

- Параметры argon2id зашиты в адаптер и не настраиваются из конфига: 4.7 фиксирует их.
- Хэш пароля считается в потоке библиотеки (`@node-rs/argon2` — асинхронные функции на пуле потоков).

## Связи

- Порты: `PasswordHasher`, `OpaqueTokens` из `@swag/identity-core`. Только типы.
- Использует: `@node-rs/argon2`, `@swag/identity-core`, `node:crypto`.
- Потребитель: оболочка `apps/identity` (T-16), собирает адаптеры и передаёт в `createIdentityCore`.

## Ключевые решения

- Алгоритм задан числом `2` (= `Algorithm.Argon2id`): `const enum` из `@node-rs/argon2` не доступен при `verbatimModuleSyntax`. Параметры — точно из 4.7, версия по умолчанию (0x13 = `v=19`).
- Хэш токена — SHA-256 от строки base64url, та же функция `hash` для выдачи и для поиска: хранилище и выдача не расходятся по кодировке.
