# @swag/node-example

Пример пакета узла: программа `example/echo@1.0.0` — возвращает входной текст с префиксом из настроек. Пакет показывает, что тип узла подключается без правки ядер (спека 021, REQ-021-15): ставится пакет, выгружается манифест, имя пакета попадает в `NODE_PACKAGES`. Эталон для авторов узлов.

## Задачи

- Показать полный путь автора узла: определение на `defineNode`, проверка `runNode` без платформы, выгрузка `swag-node.json`.
- Служить эталоном для тестов спеки 021: совпадение манифеста с определением (AC-021-15), импорты только `zod` и `@swag/node-sdk` (AC-021-16), вход, выход и настройки по схемам (AC-021-11).

## Что внутри сейчас

- `src/node.ts` — `export default defineNode({...})`: `type: 'example/echo'`, `version: '1.0.0'`, `kind: 'program'`, настройки `prefix` (до 40 символов, по умолчанию пусто), вход `text` (до 4000 символов), выход `text`. Обработчик: `prefix + text`.
- `swag-node.json` — манифест, выгруженный командой `npm run nodes:manifest`. Не править руками.
- `test/node.test.ts` — тесты AC-021-11, AC-021-15, AC-021-16.

## Как написать узел

1. Опишите схемы на Zod и определение в `src/node.ts` через `defineNode`. Вид `program` требует `inputs` и `outputs`; вид `connector` — `operations`; вид `trigger` и `channel` — `poll` (и `send` у канала). Обработчики получают типы из схем.
2. Не используйте `.transform` и `.pipe` в схемах узла: JSON Schema их теряет (правило из README `@swag/node-sdk`).
3. Проверьте обработчик без платформы. В тесте:

   ```ts
   import { createTestContext, runNode } from '@swag/node-sdk/testing';
   import echo from '../src/node.ts';

   const ctx = createTestContext(echo, { settings: { prefix: '> ' } });
   await runNode(echo, ctx, { text: 'hi' }); // { text: '> hi' }
   ```

   `runNode` проверяет вход и выход по схемам, `createTestContext` — настройки; ошибки — `NodeError` с кодом.

4. Выгрузите манифест из корня репозитория:

   ```bash
   npm run nodes:manifest
   ```

   Команда импортирует `src/node.ts` каждого пакета `packages/node-*` (кроме `node-sdk`) и пишет `swag-node.json`. Повторный запуск не меняет файл. Манифест коммитится вместе с кодом.

5. Запустите тесты пакета: `npx vitest run packages/node-example`. Тест AC-021-15 падает, если `swag-node.json` не выгружен после правки определения.

## Подключение к платформе

`api` читает только `swag-node.json` пакетов, перечисленных в `NODE_PACKAGES` (спека 021, 4.7, 4.9). Код пакета в процессе `api` не исполняется. Строка в `NODE_PACKAGES` и загрузка манифестов в `api` появятся в T-9…T-11 спеки 021; до тех пор тип виден только через тесты пакета.

## Ограничения

- Пакет — пример. Не публикуется; сторонние пакеты узлов платформа пока не принимает (спека 026).
- Исполнение `execute` на платформе — спека 026; здесь только тестовая обвязка.

## Связи

- Использует: `@swag/node-sdk` (`defineNode`, `toManifest`, `@swag/node-sdk/testing`), `zod`.
- Читает: `api` через `swag-node.json` (с T-10/T-11).

## Ключевые решения

- Программа описана одним определением и выгружается в манифест, а не регистрируется в коде `api` (021, Q-3, REQ-021-11).
- `swag-node.json` генерируется командой, а не пишется руками, и тест AC-021-15 держит его в синхроне с определением (REQ-021-12).

## Спеки

- 021 — REQ-021-11, REQ-021-12, REQ-021-15; AC-021-11, AC-021-15, AC-021-16.
