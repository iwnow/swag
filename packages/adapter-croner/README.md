# @swag/adapter-croner

Адаптер порта `CronSchedule` на `croner`: проверка cron-выражения и часового пояса и ближайшее срабатывание (спека 033, 4.5).

## Задачи

- Проверять расписание при сохранении процесса в `api` (`check`: `ok`, `invalid_cron`, `invalid_timezone`; AC-033-10).
- Вычислять следующее срабатывание строго после заданного момента, с учётом часового пояса (`next`; AC-033-10).

## Что внутри сейчас

- `createCronerSchedule()` — объект `CronSchedule`.
- `test/croner.test.ts` — AC-033-10: пример из спеки, невалидный cron и пояс, шесть полей, `next` строго после `after`.

## Ограничения

- Только пять полей без секунд: croner принимает и шесть (секунды в конце), поэтому число полей проверяется в адаптере до разбора.
- `next` для невалидного выражения или пояса бросает исключение; вызывающий сначала проверяет `check`.
- Выражение без будущих срабатываний (например, 31 февраля) даёт `null`.

## Связи

- Порт `CronSchedule` объявляют ядра `api-core` и `scheduler-core`; адаптер реализует его структурно, без импорта из ядра.
- Зависимость: `croner` 9.1.0 (точная версия, по спеке 033).

## Ключевые решения

- Пояс проверяется отдельно через `Intl.DateTimeFormat` до разбора cron, чтобы отличать `invalid_timezone` от `invalid_cron`.
- Версия `croner` закреплена точно (`--save-exact`): поведение разбора полей и часовых поясов меняется между версиями.
