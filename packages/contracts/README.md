# @swag/contracts

Общие схемы и типы платформы: то, о чём должны одинаково договориться ядра, оболочки и UI. Схемы Zod и выведенные из них типы TypeScript.

## Задачи

- Единый формат данных между сервисами: события, записи ledger, план роя, сообщения шины.
- Проверка данных на границах: оболочка или адаптер проверяет вход схемой из `contracts`, ядро получает уже валидные объекты.

## Что внутри сейчас

- `ServiceInfo` — `{ service: 'api' | 'orchestrator' | 'agent', version }`, его возвращает `info()` каждого ядра.

## Ограничения

- Только схемы и типы, без логики и без побочных эффектов при импорте.
- Зависимость одна — `zod`. Пакет входит в белый список ядер, поэтому должен быть так же чист: без Node API, env и инфраструктуры. `tsconfig` настроен как у ядер (без `@types/node` и DOM), но `arch:check` проверяет только `*-core` — импорты `contracts` им пока не проверяются (заметка N-3 в [notes.md](../../docs/spec/notes.md)).
- Имена — из [глоссария](../../docs/spec/glossary.md). Изменение схемы, которую уже используют, — правка контракта в спеке, а не только в коде.

## Связи

- Используют: все ядра и оболочки.

## Спеки

- 000 — `ServiceInfo`.
- 001 — рой, агенты с ролями, события; 004 — ledger; 009 — `SwarmPlan`; далее каждая спека добавляет свои контракты ([реестр](../../docs/spec/README.md#реестр-спек)).
