# @swag/agent-core

Ядро агента: детерминированная «эстафета» без LLM (спека 001, 4.7.2). Каждое сообщение роя агент дописывает строкой от своей роли и передаёт следующему в цепочке, а последний отдаёт результат роя.

## Задачи

- `start()`: подписаться на свои входящие (`inbox`), затем опубликовать `agent.started`.
- На каждое сообщение: `agent.working`, пауза `stepDelayMs` через порт таймера, строка `text + '\n' + name + ' (' + role + '): ok'`, далее `BusMessage` к следующему агенту или `agent.result`.
- Сообщения обрабатываются по одному, по порядку поступления.

## Что внутри сейчас

- `createAgentCore(deps)` с портами `AgentBus`, `Clock`, `IdGenerator`, `Timers`, `Logger`.
- Тесты: `test/agent-core.test.ts` — AC-001-19.

## Ограничения

Правила ядра ([архитектура](../../docs/architecture.md), [спека 000, 4.2](../../docs/spec/000-foundation.md#42-правила-ядра-и-оболочки)):

- Зависимости — `zod`, `@swag/contracts`.
- Нет окружения и инфраструктуры: шина, часы и таймеры — порты.

В 001 нет LLM, инструментов и журнала инструментов: это спеки 002 и 008.

## Связи

- Оболочка: `apps/agent` (процесс в песочнице).
- Шина: `@swag/adapter-nats` через порт `AgentBus`.
- Использует: `@swag/contracts`.

## Ключевые решения

- Сообщения обрабатываются цепочкой промисов (`queue`): следующее не начинается раньше окончания предыдущего (4.7.2, п. 3).
- Сообщение, адресованное не этому агенту, отбрасывается с предупреждением (защита от ошибки подписки).
- `agent.started` публикуется после подписки, как в 4.7.2 п. 1.
