# @swag/cabinet

Личный кабинет (Angular). В 001 — самостоятельное приложение с экранами роя; в 014 станет микрофронтендом каркаса.

## Задачи

- `/` — список роёв: задача, статус, число агентов, время; кнопка «Новый рой».
- `/swarms/new` — форма: задача, «Бюджет, $» роя (по умолчанию `0.50`, шаг `0.01`) и агенты (имя, роль, модель из `PlatformModel`, по умолчанию `chat-small`, «Бюджет агента, $» — необязательный, пустое поле — бюджета нет; «Лимит ответа, токенов» у роя и у агента — необязательный, пустое поле — значение по умолчанию, спека 031, 4.6). Первый агент — вход: получает задачу и завершает рой через `finish` (спека 022). Поля бюджета переводятся в micro-USD функцией `swarmFormInput` из `@swag/ui-core` (спека 004, 4.8), поля лимита ответа — в `maxTokens` той же функцией (спека 031, 4.5). Ответ `402 insufficient_balance` (спека 013, 4.11) выводится текстом «Недостаточно средств: доступно $X»: `X` — `formatUsd(availableMicroUsd)` из `GET /organizations/:orgId/balance`, перечитанного после отказа; если перечитать не удалось — текст ошибки сервера.
- `/balance` — страница «Баланс» организации (спека 013, 4.11): три числа «Баланс», «В резерве», «Доступно» (`formatUsd`), история «Дата / Вид / Сумма / Рой / Комментарий» от новых к старым, кнопка «Ещё» по `nextBefore` (скрыта, когда страниц больше нет). Форма «Пополнение» — только при праве `balance.topup` у роли (`ROLE_PERMISSIONS`): сумма в долларах переводится `usdToMicro`, тело проверяется схемой `TopupRequest` из `@swag/contracts`, пустой комментарий уходит как `null`; после успеха баланс и история перечитываются с первой страницы; ошибка ответа — текстом под формой. Пункт «Баланс» в шапке — только у сессии с организацией; супервизору страница говорит, что баланс доступен пользователям организации.
- `/swarms/:id` — строка денег над графом (потрачено из бюджета, остаток, расход за последнюю минуту — `formatSwarmMoney` и `spentLastMinute`; обновляется по каждому событию и раз в 5 с), граф (агенты по кругу, цвет по статусу, модель и число шагов в узле, на рёбрах стрелка и число сообщений), список агентов с суммой «потрачено» и бюджетом, если он задан (`formatUsd`), лента событий, результат или причина ошибки (`budget_exceeded` — «бюджет исчерпан», `gateway_unavailable` — «шлюз моделей недоступен», `detail` рядом), «Стоп» для активного роя. Обновление — из WebSocket. У события с `traceId` в ленте — ссылка «Трейс» в новой вкладке (спека 016). Событие `llm.call` выводится строкой вызова модели через `formatLlmCall` из `@swag/ui-core` (спека 002, 4.11), `agent.step` — строкой шага через `formatAgentStep` (спека 022, 4.10). `agent.idle` в ленте без особого формата — пустое описание, как у прочих событий без строки. `bus.message`, которое получатель не начал обрабатывать, помечается «не прочитано» (спека 030, REQ-030-6): вычисляет `unreadMessageIds` из `@swag/ui-core` по ленте и статусу роя, компонент только выводит отметку классом `unread`.

## Что внутри сейчас

- `src/app/api.ts` — адаптеры портов `ui-core`: REST и WebSocket по относительному пути `/api`; `createSwarmsApi(session)` и `createSwarmStream(session)` кладут `Authorization: Bearer` (REST) и подпротокол `swag.bearer.<token>` (WebSocket); на `401` — `renew()` и один повтор, на закрытие `4401` потока — `renew()`, переподключение (`onError` ui-core) только после удачного обновления; без токена поток не открывается и не переподключается.
- `src/app/auth-api.ts` — адаптер `AuthApi` из `ui-core` на `fetch` по `/auth` (`credentials: 'same-origin'`); ошибка с полем `code` из тела `{ error: { code } }`.
- `src/app/api.ts` (баланс, 013, 4.11) — `createBalanceApi(session)`: `getBalance`, `listBalanceEntries(orgId, before)`, `topup`; тот же способ токена и разбора ошибок, что у `/swarms`. Ошибка ответа — `ApiError` с полями `status` и `code` (ветка `402` в форме роя).
- `src/app/session.ts` — токен `SESSION`: один `AuthSessionKeeper` на приложение; `currentUser(session)` — роль и `orgId` из claims токена доступа.
- `src/app/balance.page.ts` — страница `/balance` (спека 013, 4.11).
- `src/app/auth.guard.ts` — guard маршрутов роёв: токен есть или `restore()` по cookie, иначе `/login`.
- `src/app/login.page.ts` — страница `/login`: email, пароль, текст ошибки по коду (русский).
- `src/app/app.ts` — шапка с пунктом «Баланс» (только у сессии с организацией) и кнопкой «Выйти» (вне `/login`): `logout()` и переход на `/login`; `onSignedOut` → `/login`.
- `src/app/ui.ts` — `ui-core` в DI-токене `UI`; `TRACE_URL_TEMPLATE` — шаблон ссылки на трейс в Grafana Explore.
- `src/app/swarm-graph.ts` — граф роя, чистый SVG без библиотеки (Q-4). Геометрия — чистые функции `layoutNodes` (узлы по кругу) и `edgePath` (путь ребра, дуга, петля).
- Страницы: `swarm-list.page.ts`, `swarm-new.page.ts`, `swarm.page.ts`.
- `proxy.conf.json` — `/api` → `api:3000` (снимает префикс; WebSocket включён); `/auth` → `identity:3003` без снятия префикса; `/grafana` → `lgtm:3000` без снятия префикса (Grafana на подпути). `/internal` не проксируется.
- `Dockerfile` — dev-образ для `npm run up` (`ng serve`).

## Ограничения

- Только `ng serve` (Q-4). Скрипт `build` (`ng build`) в `package.json` есть, но в CI и в Docker-образе не используется; раздачи собранного приложения в 001 нет.
- Компоненты не содержат правил: валидация, перевод денег, тексты причин, состояние роя и переподключение — в `@swag/ui-core`. Компонент передаёт значения полей и выводит готовые строки.
- Пользовательский текст выводится только интерполяцией Angular, без `innerHTML`.
- Вход — спека 024 (T-16): страница `/login`, токен доступа только в памяти страницы, обновление по cookie `swag_refresh`. Экранов регистрации, приглашения и админки нет (014).
- Тестов в cabinet нет: Angular-тестового раннера в проекте нет. Компоненты проверяются сборкой `ng build` и ручной проверкой UI (T-20). Логика денег и её тесты — в `@swag/ui-core` (`packages/ui-core/test/money-input.test.ts`).
- Превышение бюджета агента над бюджетом роя форма не проверяет: `SwarmCreateRequest` этого не требует, сервер отвечает `400`, текст выводится в ошибке формы (спека 004, 4.7, D-105).

## Связи

- Логика: `@swag/ui-core`; типы и проекция: `@swag/contracts`, `@swag/api-integration`.
- Бэкенд: `apps/api` через прокси.

## Ключевые решения

- Angular 22.2.3 (`@angular/*`, `@angular/build`, `@angular/cli`), состояние — signals. Версии точные (`save-exact`). Zoneless — по умолчанию с Angular 21 (angular.dev/guide/zoneless), отдельного провайдера в `app.config.ts` нет.
- `proxy.conf.json` подключён через `angular.json` → `serve.options.proxyConfig`. `ws: true` передаётся в прокси Vite, `pathRewrite` `@angular/build` переводит в `rewrite` (`utils/load-proxy-config.js`). angular.dev (https://angular.dev/tools/cli/serve) описывает только `target` и `secure`; поведение `ws`/`pathRewrite` — по исходникам установленного `@angular/build` 22.2.3. `provideBrowserGlobalErrorListeners` есть в типах `@angular/core`.
- Граф — собственный SVG-компонент без библиотеки (Q-4). Узлы по кругу в порядке id, радиус не меньше 120 px и не меньше, чем нужно для зазора `NODE_GAP` между соседними узлами. Встречные рёбра `a → b` и `b → a` рисуются квадратичными кривыми внутрь круга на разную глубину (15 и 60 px), подписи пары — ближе к началу своей дуги, поэтому не накладываются. Наружу дуга не выгибается: при 5 и более агентах она заходила бы под соседний узел (ревью T-15); параметры проверены расчётом для 2–8 агентов; одиночное ребро — прямая. Петля (ребро на себя, по 4.10) — дуга наружу от круга. Подписи с белой обводкой, чтобы читались на линии.
- Шаги агента (`agent.step`) — строкой ленты через `formatAgentStep`, без отдельного экрана.
- Деньги (спека 004, 4.8): перевод полей формы — `swarmFormInput` из `ui-core` (доллары → micro-USD, пустой бюджет агента — `null`); некорректный ввод даёт `NaN`, который отсекает `SwarmCreateRequest`. Все суммы на экране — через `formatUsd` и `formatSwarmMoney`.
- Строка денег обновляется таймером раз в 5 с (`MONEY_TICK_MS` в `swarm.page.ts`) и по каждому событию. Таймер запускается в конструкторе страницы и очищается в `ngOnDestroy`, поэтому на другой странице не работает. Таймер ui-core (`Timers`) для него не используется: он нужен только для переподключения потока.
- Тексты причин `budget_exceeded` и `gateway_unavailable` — `failureReasonText` из `ui-core` (4.8), прочие причины выводятся как пришли (D-107).
- Логика вне компонентов: `createUiCore` из `@swag/ui-core` подключается через токен `UI`.
- Сессия (024, 4.15): `createAuthSessionKeeper` из `@swag/ui-core` в токене `SESSION`. Один `renew()` на все одновременные `401` — в `ui-core` через общий промис. Неудача обновления — `onSignedOut` → `/login`. Трактовка: при закрытии потока `4401` вызывается `renew()`; только при `true` поток сообщает `onError`, и `ui-core` переподключается через 1 с с новым токеном; при `false` переподключения нет, `onSignedOut` уводит на `/login`. Без токена поток не открывается и не сообщает `onError`: сессии нет, `onSignedOut`/guard уведёт на `/login`, бесконечного переподключения нет.
- Баланс (013, 4.11): роль и `orgId` берутся из claims access-токена (`AccessTokenClaims` из `@swag/contracts`), а не из `AuthSession.user`: `AuthSessionKeeper` хранит только токен, и вход/обновление не отдают пользователя. Claims читаются при каждом вызове, поэтому после `renew()` они актуальны. Это только для показа пункта и формы; права проверяет API.
- Вход не проверяет `Authorization` сам: guard смотрит только наличие токена в памяти; истёкший токен обновляется на первом `401` от `api`.
- Dev-сервер и прокси `/api` → `api:3000` (Q-4). Отклонение: в CI сборка `ng build` не запускается (спека требует `npm run check` без UI-шага).
- `allowImportingTsExtensions` и `rewriteRelativeImportExtensions` в tsconfig — чтобы Angular собирал TS-исходники `packages/*` с расширениями `.ts`.
- Ссылка «Трейс» (016, Q-6): относительный адрес `/grafana/explore?...` через прокси `ng serve`, без конфигурации в UI. Шаблон — Explore Grafana с источником Tempo (uid `tempo` в `grafana/otel-lgtm`), запрос TraceQL — сам `traceId`, диапазон — последние 7 дней. Адрес строит `ui-core.traceUrl`, компонент только рисует `<a target="_blank" rel="noopener">`. SDK OpenTelemetry в браузере нет (Q-7).
