# apps/agent

Оболочка агента: процесс в песочнице. Поднимает телеметрию, подключает `agent-core` к NATS и пишет баннер запуска логом.

## Задачи

- Прочитать `AgentConfig` из env, подписаться на свой inbox, опубликовать `agent.started`, выполнять эстафету (спека 001, 4.7).
- Телеметрия до подключения к NATS; старт — в спане `agent.start` с родителем из `TRACEPARENT` (спека 016, 4.7).
- Ошибка конфигурации или подключения: `error`-лог `agent start failed` с `err`, сброс телеметрии, выход с кодом 1 (REQ-016-8).
- По `SIGTERM` закрыть соединение с NATS, сбросить телеметрию и выйти с кодом 0 (REQ-001-17).

## Что внутри сейчас

- `src/run.ts` — баннер: версия Node, версия агента, `agent ok`.
- `src/start.ts` — `startAgentProcess(deps)`: телеметрия, конфигурация, адаптер NATS, ядро и запуск в спане `agent.start`; зависимости (env, `startTelemetry`, `connect`, `exit`) внедряются.
- `src/main.ts` — сборка настоящих зависимостей и обработка `SIGTERM`.
- Тесты: `test/run.test.ts` (баннер), `test/start.test.ts` (AC-016-11 — NATS недоступен).

## Ограничения

- Агент без LLM и инструментов: вызов gateway и агентный цикл — 022 (спека 002, раздел «Не входит»).
- Токен пользователя и доступ к данным платформы в песочнице не нужны и не передаются. Из переменных телеметрии агент получает только `TRACEPARENT` и `OTEL_EXPORTER_OTLP_ENDPOINT` (REQ-016-14).
- Уровень логов агента — `info`: `debug message handled` из ядра в работе не выводится.

## Связи

- Ядро: `@swag/agent-core`. Адаптеры: `@swag/adapter-nats`, `@swag/adapter-telemetry`. Конфигурация: `@swag/config`.

## Ключевые решения

- Баннер `node/agent/agent ok` пишется до подключения к NATS: это старт процесса, а не готовность эстафеты. С 016 строки баннера — записи `info` схемы `LogRecord`, а не голый текст в stdout (REQ-016-5).
- Переменные телеметрии и id агента разбираются отдельно от полной конфигурации (`AgentConfig.pick`): ошибка конфигурации тоже пишется логом с `swarmId`, `agentId` и `traceId`, если эти значения валидны.
- `agent start failed` пишется внутри спана `agent.start`, поэтому у записи `traceId` из `TRACEPARENT`; спан получает статус `ERROR`.
- Механизм теста AC-016-11 — вызов `startAgentProcess` с внедрёнными зависимостями, а не дочерний процесс: настоящие `adapter-telemetry` и `adapter-nats` (NATS на закрытом порту), экспорт логов в память, `exit` — фейк, порядок «сброс → выход» проверяется.
- Образ агента `apps/agent/Dockerfile` собирается отдельно (`npm run agent:image`, профиль `agent`) и не стартует в `npm run up`.
- `SIGTERM` → `drain` NATS → сброс телеметрии → `exit(0)`.

## Спеки

- 000 — заглушка. 001 — 4.7. 016 — 4.7, REQ-016-8, AC-016-11. 002 — песочница не получает ключи провайдеров и `LLM_GATEWAY_TOKEN` (AC-002-22 — в `orchestrator-core`).
