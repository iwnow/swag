# Отложенные вопросы

Вопросы, которые возникли при реализации спек, но не блокируют текущую: решение отложено до спеки, где оно понадобится, или до отдельной спеки. Блокирующие вопросы по-прежнему пишутся в раздел 9 спеки (`Q-n`), а не сюда.

Формат: `D-n` — номер по порядку, не переиспользуется. Откуда — спека и место, где вопрос возник. Куда — спека, в которой его решать (номер из [реестра](README.md#реестр-спек)), или «приёмка NNN».

Жизненный цикл: при черновике каждой новой спеки `/write-spec` забирает отсюда вопросы, которые можно решить в ней, переносит их в её раздел 9 как `Q-k` со ссылкой «из D-n» и удаляет отсюда. Вопросы приёмки удаляются, когда человек ответил, а ответ записан в спеку. Здесь остаётся только то, что ещё ждёт своей спеки ([процесс](README.md#цикл-работы-со-спекой)).

- [ ] **D-1. Переход на TypeScript 7 и `arch:check`.** *(из 000, журнал; куда — 011; Claude, 2026-10-21)*
  Требование 000 4.5 «разбирать импорты через TypeScript compiler API» привязывает `arch:check` к TypeScript ≤ 6: в TypeScript 7 (порт на Go) этого API нет, поэтому в 000 стоит TypeScript 6.0.3. Переход на 7 так же блокирует typescript-eslint 8.72 (поддерживает TS < 6.1).
  Варианты: **(а)** парсер, не зависящий от версии TS (`oxc-parser`, `es-module-lexer`) — `arch:check` остаётся отдельной командой; **(б)** правило ESLint `no-restricted-imports` для `packages/*-core`, а `arch:check` проверяет только `package.json` ядер — меньше своего кода, но проверка импортов зависит от линтера; **(в)** ждать JS API у TypeScript 7 — сроки неизвестны.
