# Swag

Swag (swarm + agent) — платформа роёв агентов: оркестратор поднимает песочницы, агентам подключаются скиллы из реестра, агенты общаются через изолированную шину роя, пользователь видит граф роя и расходы в реальном времени.

- Что и зачем — [AI_PLATFORM_ROADMAP.md](AI_PLATFORM_ROADMAP.md).
- Как именно — спецификации в [docs/spec/](docs/spec/README.md).
- Устройство кода — [docs/architecture.md](docs/architecture.md).
- Термины и имена в коде — [docs/spec/glossary.md](docs/spec/glossary.md).

## Архитектура: ядро и оболочка

Логика пишется только в ядрах `packages/<имя>-core` — чистый TypeScript без фреймворков, Node API, env и клиентов инфраструктуры; всё внешнее — через порты, которые объявляет ядро. Оболочки `apps/<имя>` (Fastify, процесс агента, UI) только собирают адаптеры, вызывают фабрику ядра и переводят вход и выход. Пакеты — `@swag/<имя>`. Правила целиком — [docs/architecture.md](docs/architecture.md); нарушение границ ловит `npm run arch:check`.

## Разработка идёт по спекам

Код пишется только по спеке со статусом `ready` или `in-progress`. Процесс, статусы и цикл «черновик → ready → реализация → review → приёмка → done» — [docs/spec/README.md](docs/spec/README.md#цикл-работы-со-спекой). Новая спека: `/write-spec <тема>`. Реализация: `/implement-spec NNN`.

В начале сессии: прочитай реестр спек в [docs/spec/README.md](docs/spec/README.md#реестр-спек), чтобы знать, какая спека в каком статусе и что следующее.

### Правила для агента

1. **Спека — источник требований.** Разделы 3–7 (требования, контракты, критерии приёмки, NFR, безопасность) агент не меняет. Агент меняет только: `status` и `updated` во frontmatter, отметки задач `[x]`, раздел «Открытые вопросы» (добавляет) и «Журнал реализации».
2. **Не додумывать.** Пробел, противоречие или требование, которое невозможно выполнить, — это повод остановиться: записать вопрос `Q-n` в раздел 9, поставить `status: blocked`, закоммитить и сообщить человеку. Не выбирать «разумный вариант» молча.
   **Вопросы, которые не блокируют текущую спеку,** — в [docs/spec/questions.md](docs/spec/questions.md) как `D-n`: откуда вопрос, в какой спеке его решать, варианты. Трактовка, которую агент принял сам, тоже записывается туда на подтверждение человека. Блокирует работу — `Q-n` в спеке, не блокирует — `D-n` в `questions.md`.
3. **Ничего сверх спеки.** То, что в «Не входит», не делается. Полезная идея или замеченный технический долг за пределами спеки — заметка `N-n` в [docs/spec/notes.md](docs/spec/notes.md), не в код.
4. **Тест на каждый критерий.** Каждый `AC-NNN-n` закрыт тестом, в имени которого есть id: `it('AC-003-2: ...')`. Критерии `[manual]` — проверка выполнена и результат приложен в журнал.
5. **Имена — из глоссария.** Нового термина нет в глоссарии — это открытый вопрос.
6. **Перед статусом `review` всё зелёное:** `npm run check` (формат, линтер, типы, сборка, тесты, трассировка спек). Если что-то не проходит и починить нельзя в рамках спеки — `blocked`.
7. **У каждого пакета `apps/*` и `packages/*` есть `README.md`** по общей схеме: что это и зачем, задачи, что внутри сейчас, ограничения, связи, спеки. Новый пакет — сразу с README; изменение назначения, ограничений или связей пакета — правка его README в той же задаче.
8. **Отклонения фиксируются.** Любое отличие реализации от буквы спеки (например, версия библиотеки отличается) — строка в журнале реализации с причиной.

### Git

- Ветка: `spec/NNN-slug` от основной ветки.
- Коммит на каждую задачу T-n. Сообщения на русском, conventional commits с ссылкой на спеку: `feat: spec:003 T-2 виртуальные ключи на агента`.
- Без force push. Push и merge request — только по команде человека.

### Безопасность

- Секреты — только в `.env` (не в git) и в секретах CI. В коде, тестах, фикстурах и логах — только явно фейковые значения.
- Ключи провайдеров моделей никогда не попадают в песочницу и в код агента.
- Порты локальной инфраструктуры публикуются только на `127.0.0.1`.
