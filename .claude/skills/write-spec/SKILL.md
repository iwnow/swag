# Черновик спеки

## Шаги

1. Прочитай `docs/spec/README.md` (процесс, реестр), `docs/spec/_template.md`, `docs/spec/glossary.md`, `AI_PLATFORM_ROADMAP.md` и спеки, от которых будет зависеть новая (их раздел 4 «Контракты»).
2. Номер: если тема есть в реестре — его номер; иначе следующий свободный. Файл `docs/spec/NNN-slug.md`, slug — латиницей, через дефис.
3. Заполни шаблон, `status: draft`:
   - **Коротко** — блок для человека в начале: что появится, ключевые решения, что нужно от человека. Читается за минуту без остальной спеки.
   - **Контекст** — ссылка на раздел роадмапа, текущее → целевое состояние.
   - **Не входит** — явно перечисли соседние темы, которые уйдут в другие спеки.
   - **Требования** — проверяемые, с MUST/SHOULD. Без слов «быстро», «удобно» без числа.
   - **Контракты** — точные типы/схемы Zod, эндпоинты, события, таблицы, env. Согласованы с контрактами зависимостей.
   - **Критерии приёмки** — given/when/then, каждый автоматизируемый; иначе `[manual]` с описанием проверки. Покрывают каждое MUST-требование.
   - **Безопасность** — что не должно сломаться и каким AC это проверяется.
   - **Задачи** — упорядоченные, каждая со ссылками на REQ/AC и критерием готовности, размер — до нескольких часов работы агента.
4. Всё, что требует решения человека (выбор технологии, бизнес-правило, число-порог, которого нет в роадмапе), — в **Открытые вопросы**: вопрос, варианты, твоя рекомендация с причиной. Не выбирай молча.
5. Новые термины — добавь в `glossary.md`.
6. Добавь или обнови строку в реестре `docs/spec/README.md` со статусом `draft`.
7. Самопроверка перед сдачей:
   - каждое MUST покрыто хотя бы одним AC;
   - каждый AC закрыт какой-то задачей;
   - по контрактам можно писать код без догадок;
   - «Не входит» не пуст.
8. Сообщи пользователю: путь к спеке, сколько требований и критериев, список открытых вопросов. Статус `ready` ставит только человек.
