# Реализация спеки

Аргумент — номер спеки `NNN`. Файл: `docs/spec/NNN-*.md`.

## 1. Подготовка

1. Прочитай `CLAUDE.md`, `docs/spec/README.md`, `docs/spec/glossary.md` и саму спеку целиком.
2. Проверь `status`:
   - `ready` — продолжай;
   - `in-progress` — продолжи с первой неотмеченной задачи;
   - `blocked` — проверь, ответил ли человек на все вопросы раздела 9 (отмечены `[x]` и есть ответ). Если нет — остановись и перечисли неотвеченные вопросы;
   - `draft`, `review`, `done`, `superseded` — не начинай, сообщи статус и остановись.
3. Проверь `depends_on`: все перечисленные спеки должны быть `done`. Иначе — остановись и назови недостающие.
4. Прочитай спеки из `depends_on` (разделы 4 «Контракты») — твой код должен с ними совпадать.
5. Проверь `docs/spec/questions.md` и `docs/spec/notes.md`: если там остался пункт, у которого «куда»/«когда» — эта спека, значит при черновике его не забрали — это пробел (шаг 4).
6. Пройди спеку на пробелы до начала кода: каждый AC проверяем? Контракты достаточны, чтобы писать код без догадок? Нашёл пробел — сразу `blocked` (шаг 4), код не пиши.

## 2. Старт

1. Ветка `spec/NNN-slug` от основной (или переключись на неё, если уже есть).
2. Во frontmatter: `status: in-progress`, `updated: <сегодня>`. Коммит `chore: spec:NNN взята в работу`.

## 3. Задачи — по порядку, по одной

Для каждой задачи `T-n`:
1. Реализуй только то, что закрывает её REQ/AC.
2. Тесты: на каждый AC задачи тест с id в имени (`it('AC-NNN-k: ...')`). Сначала тест, который падает, потом код.
3. Прогони тесты затронутых пакетов и `npm run typecheck`. Обнови `README.md` каждого пакета, который задача создала или изменила (схема — правило 7 в `CLAUDE.md`): запиши ключевые решения задачи с причиной (библиотека и версия, устройство порта или адаптера, формат данных, отклонение, трактовка) и перепиши устаревшее под новое состояние — README описывает пакет сейчас, а не историю. Если в коде появилось имя (тип, порт, событие, статус), которого нет в `docs/spec/glossary.md`, — добавь его в глоссарий в том же коммите и отметь в журнале (правило 5 в `CLAUDE.md`).
4. Отметь `[x]` у задачи. Коммит `feat|fix|chore: spec:NNN T-n <что сделано>` (на русском).

Если в процессе обнаружилось, что спека неполна или противоречива — шаг 4.

Если вопрос не мешает текущей задаче (решение нужно в другой спеке, или ты принял трактовку, которую должен подтвердить человек), — не блокируйся: запиши `D-n` в `docs/spec/questions.md` по формату из его шапки (откуда, куда, варианты) и продолжай. Трактовку дополнительно отметь в журнале реализации.

Заметил мелкое улучшение или технический долг за пределами спеки (выбирать нечего, просто стоит сделать позже) — не делай, а запиши `N-n` в `docs/spec/notes.md`: где, когда взять в работу, что сделать.

## 4. Блокировка

1. Допиши в раздел 9 вопрос: `- [ ] **Q-k.** <конкретный вопрос, варианты ответа и их последствия> *(Claude, дата)*`.
2. `status: blocked`, `updated: <сегодня>`. Коммит `chore: spec:NNN заблокирована: Q-k`.
3. Остановись и сообщи пользователю вопрос. Не продолжай другие задачи, если они зависят от ответа.

## 5. Завершение

1. Полный прогон: `npm run check`. Всё зелёное. (Пока реализуется сама спека 000 и `npm run check` ещё нет — прогнать те команды, что уже есть.)
2. Критерии `[manual]`: выполни проверку, если она возможна локально, и приложи результат в журнал. Невозможна (например, нужен CI) — так и напиши в журнале.
3. Журнал реализации: строка с датой, веткой и последним коммитом, кратко что сделано, все отклонения от спеки с причинами.
4. NFR: если есть измеримые — приложи замеры в журнал.
5. Сверь README всех затронутых пакетов с кодом: «что внутри сейчас», ключевые решения, ограничения и связи соответствуют реализации, устаревшего нет.
6. `status: review`, `updated: <сегодня>`. Обнови статус в реестре `docs/spec/README.md`. Коммит `chore: spec:NNN готова к ревью`.
7. Отчёт пользователю: таблица AC → тест (файл:строка) → результат; отклонения; что проверено вручную и что не проверено; новые `D-n` в `questions.md` — отдельно те, что нужно решить при приёмке этой спеки; новые `N-n` в `notes.md`.

Push и merge request — только по команде пользователя.
